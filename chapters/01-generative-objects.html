Chapter 1

Generative Objects

The central abstraction of Regen is an object whose properties and composition can be determined by computations rather than only by explicit construction steps.

1.1 What Is a Generative Object?

A generative object is an object whose definition specifies how its properties, and potentially its constituent objects, are determined. The description may include values supplied by the user and expressions that compute other values.

Consider a mechanical housing whose dimensions depend on the components it contains. A conventional object might store the resulting dimensions. A generative object can represent how those dimensions are derived from its requirements. When the requirements change, the derivations remain part of the model.

1.2 Description Rather Than Construction Sequence

Imperative modeling often expresses a design as a sequence: create one piece, assign dimensions, transform another piece, and join them. A generative description instead expresses relationships such as “the housing length depends on the shaft length and required clearances.”

This does not mean that Regen performs no procedural work. Evaluation and geometry creation still take place. The distinction concerns what the programmer needs to specify: the relationships of the design rather than every step by which the current result is constructed.

1.3 Attributes

An attribute is a named property of a generative object. Some attributes are starting points for computation; others are calculated from surrounding context or other attributes. Components are another kind of attribute, describing constituent objects.

For a cylinder, its length and radius may be given directly, while volume is computed. In a different design, the volume could be the given value and the radius derived from it. The semantic meaning of a property is separate from how a particular class obtains its value.

Chapter 2 distinguishes inputs, ordinary attributes, and components.

1.4 Generative Composition

Complex objects consist of other objects. In Regen, generative composition describes constituent objects as part of a parent's definition, rather than treating the child hierarchy as an unrelated assembly step.

A mechanical assembly, for instance, might describe a shaft, bearings, and housing as components. Their properties may depend on values determined elsewhere in the assembly. The resulting instance hierarchy describes containment; it should not be confused with the attribute dependency graph that records computational relationships.

1.5 Generative Objects and Common Lisp

Regen is built around Common Lisp and CLOS. Class inheritance, generic-function dispatch, and object composition remain useful, but generative objects add declarative computed properties and generative assembly semantics.

This means the approach is not simply a procedural CAD API wrapped in Lisp syntax. It uses the language's abstraction facilities to describe reusable engineering models.

1.6 Regen Is a Live Programming Environment

Regen's ambition includes a live programming environment: programs and their objects can be examined and developed within a running Lisp image. A model is not merely a file that produces geometry and terminates.

Live development is useful when exploring relationships. A programmer can examine a running design, change definitions or inputs, and investigate the consequences. Details of evaluation and update mechanics belong in later chapters.

1.7 Expressiveness and Complexity

Declarative relationships do not eliminate complexity. They change where it lives. The system must evaluate attributes, track dependencies, invalidate computed results when appropriate, and report errors when descriptions cannot be satisfied.

The payoff is that applications can express design intent directly. A reusable abstraction can eliminate repeated construction procedures across many models. The cost is a more sophisticated generative runtime.

1.8 Summary

Generative objects express properties and composition through reusable descriptions. They are grounded in Common Lisp's object system but include computational relationships not captured by ordinary stored properties alone.
