Chapter 4 · A spatial application of generative objects

Spatial Organization with node-mixin

Generative objects do not have to be geometric. When they represent parts of a spatial assembly, however, a coordinate system makes their relationships much more expressive. Adhoc's scene-graph library supplies this functionality through node-mixin.

Source note. The class name node-mixin, the origin and rotation inputs, and the transformation macros come from adhoc-scene-graph. The quaternion function qrotation comes from 3d-math. The illustrative classes below have not been executed in a Regen image. Package imports or qualification are assumed: defobject from Adhoc, node-mixin and globally from the scene-graph package, and vec3 and qrotation from 3d-math.

4.1 From Generative Objects to Spatial Nodes

The source calls the class node-mixin; when discussing its role we may simply call an instance a node. It is a generative superclass that supplies spatial inputs and computed transformations. It does not replace the general generative object model: ordinary non-spatial objects still use defobject without inheriting from it.

(defobject positioned-shaft (node-mixin)
  :inputs ((length 100))
  :attributes
  ((local-coordinate (vec3 100 0 0))))

Here positioned-shaft inherits spatial behavior from node-mixin while declaring its own length input. The ordinary attribute local-coordinate is a point at (100, 0, 0), expressed in the shaft's own coordinate system. This is class inheritance, not component composition; an assembly can subsequently contain an instance of this class.

The implementation also has graphics-related properties, but those are not needed to understand the spatial model.

4.2 Origin: Position in a Parent Frame

The origin input describes the position of a node's local coordinate origin relative to its containing node's coordinate system. In the source, its initial expression is (vec3 0 0 0). That position is a three-dimensional vector, rather than three unrelated scalar inputs.

(defobject positioned-shaft (node-mixin)
  :inputs ((length 100)))

(defobject shaft-support (node-mixin)
  :inputs ((shaft-offset 25))
  :components
  ((main-shaft :type 'positioned-shaft
               origin (vec3 (the shaft-offset) 0 0))))

The provided-input expression origin (vec3 (the shaft-offset) 0 0) positions the child shaft at an offset determined by the assembly's shaft-offset input. It is another example of generative composition: the containing object specifies a relationship that determines the child object's input.

Here and below the vector constructors and angle expressions are shown in the same general style as the libraries' source; the examples use an assumed package context rather than a complete application initialization sequence.

4.3 Rotation: Orientation with Quaternions

Position alone is insufficient for a spatial assembly. The rotation input expresses the orientation of the child's local coordinate system relative to the parent. Its default in node-mixin is the identity quaternion, (quat 0 0 0 1).

3dm:qrotation constructs a quaternion from a rotation axis and angle. For example, a quarter-turn about the Z axis can be expressed as:

(qrotation (vec3 0 0 1) (/ pi 2))

The first argument is the axis vector; the second is the rotation angle in radians. The mathematical value (/ pi 2) represents 90 degrees. This example introduces quaternion construction without requiring the reader to manipulate quaternion components directly.

In the scene graph, a rotation-matrix attribute derives a transformation matrix from the quaternion, and the node's local matrix combines rotation and translation. Thus a rotation input participates in the node's spatial calculations.

4.4 Spatial Generative Composition

A component's origin can be driven by a provided-input expression, so its placement depends on the assembly's declared dimensions. The parent node can also be rotated, carrying all of its constituent objects with it:

(defobject shaft-support (node-mixin)
  :inputs ((shaft-offset 25))
  :components
  ((main-shaft :type 'positioned-shaft
               origin (vec3 (the shaft-offset) 0 0))))

This model places the shaft's origin at (vec3 25 0 0) in the shaft-support's local coordinate system. It does not rotate the shaft by itself; the child inherits the identity rotation supplied by node-mixin. The provided-input expression establishes a relationship between the support's offset and the shaft's placement. In the next section we rotate the support, demonstrating how the same child origin acquires a different position in global coordinates.

4.5 From Local to Global Coordinates

The shaft defines local-coordinate as (vec3 100 0 0) in its own frame. We can ask for that point's global coordinate by binding self to the shaft and using globally.

For this example, we rotate the containing shaft-support by a quarter-turn about Z. The shaft itself is not rotated relative to the support; its origin remains (25, 0, 0) in support coordinates.

(let* ((assembly (make-instance 'shaft-support
                                'rotation
                                (qrotation (vec3 0 0 1) (/ pi 2))))
       (shaft-object (send assembly main-shaft))
       (self shaft-object))
  (globally (the local-coordinate)))

The expression (the local-coordinate) reads (100, 0, 0) in the shaft's local frame. The globally macro converts it into the global frame, accounting for both the shaft's parent-relative displacement and the support's quarter-turn. In conventional right-handed, positive-angle coordinates with the support at the global origin, the expected point is approximately (0, 125, 0). This numerical expectation has not been verified in a running Regen image.

;; The globally macro expands to:
(transform-to-global-coordinate (the local-coordinate) self)

Because self is the shaft, its complete relationship to the global frame is used. Rotating the shaft alone about its own origin would move a point such as local-coordinate, but would not move the shaft's origin. Rotating the support changes the global position of both the shaft's origin and that point.

A global coordinate system is not necessarily identical to the root object's local coordinate system; the scene-graph API distinguishes those concepts.

4.5.1 Reading an Attribute Versus Transforming Its Coordinate

Package note: In these examples, locally denotes adhoc-scene-graph:locally (also writable adhoc-scene-graph::locally), not the Common Lisp special operator cl:locally. The scene-graph package shadows cl:locally; examples assume its exported macro is accessible without qualification.

The the form reads an attribute through reference chaining. By contrast, locally follows a chain to a coordinate-valued attribute and transforms that coordinate from the referenced node's frame into the frame of self.

(let* ((assembly (make-instance 'shaft-support))
       (self assembly))
  (the main-shaft local-coordinate))
;; => (VEC3 100.0 0.0 0.0)

(let* ((assembly (make-instance 'shaft-support))
       (self assembly))
  (locally main-shaft local-coordinate))

The first expression returns the attribute's raw local value. The second requests the same point in the support's frame, accounting for the child's origin. With the illustrated displacement of 25 along X and no child rotation, the expected coordinate in the support's frame is (125, 0, 0). Numerical outputs should still be confirmed in the running image.

This is a clearer use of locally than passing the child's origin input: the latter is already expressed in the parent's frame, whereas local-coordinate is explicitly defined in the shaft's own frame.

4.6 A Small Spatial Assembly

Putting the declarations together, shaft-support places its child shaft 25 units along its local X-axis. The shaft defines a point another 100 units along its own X-axis. Rotating the support by 90 degrees rotates the entire arrangement in global space.

(let* ((assembly (make-instance 'shaft-support
                                'rotation
                                (qrotation (vec3 0 0 1) (/ pi 2))))
       (shaft-object (send assembly main-shaft))
       (self shaft-object))
  (globally (the local-coordinate)))

The result expresses the shaft's declared point in global coordinates. The example combines an ordinary attribute, component composition, an input-driven placement, quaternion rotation, reference chaining, and spatial transformation. Detailed matrix operations remain outside this introductory chapter.

4.7 What Comes Later

This chapter introduces spatial organization as an application of generative composition, not as a complete geometry course. Later topics include transformations between any two node frames, the as and locally macros, quaternion operations, geometry defined in local frames, and dependency/invalidation behavior when placements change.

As in earlier chapters, this is a conceptual progression: the object model and its declarative attribute semantics come first; spatial representation is a powerful but optional capability built on top of them.
