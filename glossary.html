Terminology Index

Concise definitions with links to their discussion in the guide. Foundational notions such as declarative programming, design intent, knowledge-based engineering, ontology, and schema are distinguished from Regen features planned for future development.

ACDGIKLMOPST

A

Attribute
A named property of a generative object. The property's semantics need not prescribe how its value is obtained. Read discussion.
Attribute kind
A category of attribute with its own semantics. Inputs, ordinary attributes, and components are three essential kinds in generative Regen objects, but the system is extensible and may have many more kinds. Do not confuse attribute kind with a Common Lisp type. Read discussion.

C

Class
Specifically, a CLOS class. The broader term type includes classes and other Common Lisp types. Read discussion.
Component
An attribute specifying a child generative object, its class, or relevant values. Not an ECS component. Read discussion.
Composition
Constructing a larger object from distinct constituent objects rather than specializing a single class. Read discussion.
Computed value
A value obtained by evaluating an attribute expression, distinguished from an explicitly assigned value. Read discussion.

D

Declarative programming
A programming approach that expresses required properties, relationships, or results rather than explicitly orchestrating every computation step. Declarative expressions may still invoke procedural computations. Read discussion.
Dependency graph
The graph of computational dependencies between attributes. Distinct from the hierarchy of component instances. A deeper treatment is planned. Read discussion.
Design intent
The purpose, requirements, rationale, constraints, and relationships that explain why a design is organized as it is and how it should respond to change. Making design intent explicitly representable and inspectable is a subject for deeper treatment in the Regen Guide; no new intent API is asserted here. Read discussion.

G

Generative composition
Specifying nested generative objects as part of a generative definition, including relationships that determine their properties. Read discussion.
Generative object
An object defined through declarative properties and relationships that determine its properties and potentially its child objects. Read discussion.

I

Inheritance
Reuse or specialization through CLOS class relationships; different from component composition or semantic protocol conformance. Read discussion.
Input
An attribute serving as a starting point for computations. Optional inputs can use their defining expression until assigned. Read discussion.
Instance hierarchy
The parent/child structure of constituent generative objects; not the same as computational attribute dependencies. Read discussion.

K

Knowledge-based engineering (KBE)
The use of explicit engineering knowledge, rules, relationships, and computational models to automate, configure, evaluate, or modify engineering designs. It is an application area of knowledge-based systems. Read discussion.
Knowledge-based system
A computational system that uses represented domain knowledge to support reasoning, decisions, or action. Regen is framed as a knowledge-based system for generative engineering. Read discussion.
Knowledge representation
The field and practice of encoding concepts, facts, relationships, and rules in forms suitable for computational use. Knowledge-based systems apply knowledge-representation techniques; the two are not literal set-theoretic subsets. Read discussion.

L

Live programming environment
A running environment where objects and definitions can be inspected, revised, and reevaluated during development. Read discussion.

M

Metaclass
A CLOS class whose instances are classes. Detailed MOP topics are deferred to advanced chapters. Read discussion.

O

Object protocol
A semantic contract that can be satisfied by unrelated CLOS classes without requiring common inheritance. Read discussion.
Ordinary attribute
An attribute ordinarily expressing a computed property; some may also support explicit assignment. Read discussion.
Ontology
An explicit conceptualization of a domain, defining its concepts and relationships, sometimes with formal axioms. Ontologies are an approach within knowledge representation; they can incorporate schema-like constraints but are not simply a superset of all schemas or knowledge-based systems. Read discussion.

P

Protocol
A set of semantic requirements for properties or operations, independently of any one implementation class. Read discussion.

S

Schema
A specification of the structure and permitted organization of data or entities, potentially including types, properties, and constraints. Schemas and ontologies can overlap, but neither term should be treated as an exact synonym for the other. Read discussion.
Settable
A property supporting explicit assignment. Settable status should not be confused with whether its normal value is computed. Read discussion.
Specializer
A method specializer, such as a CLOS class specializer or an eql specializer; not a synonym for type. Read discussion.
Struct
A Common Lisp structure defined with defstruct, distinguished here from a CLOS class. Read discussion.

T

Type
The broad Common Lisp type concept, including CLOS classes, struct types, and types introduced with deftype. Read discussion.
